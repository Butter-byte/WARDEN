Run these INSIDE the Mininet CLI (mininet>) once start_topology.sh has booted it.
Watch the controller's terminal at the same time -- it logs every VLAN
assignment decision live, which is the best thing to show the reviewer.

1. Prove same-VLAN hosts can talk (both staff, different switches):
   mininet> h1 ping -c 3 h3

2. Prove same-VLAN hosts can talk (both guest, different switches):
   mininet> h2 ping -c 3 h4

3. Prove cross-VLAN hosts CANNOT talk (same switch, different VLAN):
   mininet> h1 ping -c 3 h2

4. Prove cross-VLAN hosts CANNOT talk (different switch, different VLAN):
   mininet> h1 ping -c 3 h4

5. Full matrix at once (expect exactly 50% loss -- only same-VLAN pairs succeed):
   mininet> pingall

6. Inspect the flows the controller actually installed on a switch:
   mininet> sh ovs-ofctl -O OpenFlow13 dump-flows s1
   mininet> sh ovs-ofctl -O OpenFlow13 dump-flows s2

--- Mobility proof: h1 roams from s1 to s2, keeps its VLAN ---
topo.py already gives h1 a second (standby) link to s2 on port 4, brought
down at boot. This sequence makes it live -- it's the single best moment
to show the reviewer, since it proves VLAN assignment follows identity,
not the port it's plugged into.

1. Baseline -- confirm h1 reaches h3 (both staff/VLAN10) via s1:
   mininet> h1 ping -c 3 h3

2. "Unplug" h1 from s1 and "plug it in" at s2 instead (both ends of each
   link go down/up together, so this is the mininet-correct way to do it
   -- don't use `ip link set` from inside the host alone):
   mininet> py net.configLinkStatus('h1', 's1', 'down')
   mininet> py net.configLinkStatus('h1', 's2', 'up')

3. Move h1's IP from its old interface to the new one (the IP doesn't
   follow automatically -- this models a device reassociating at a new
   access point):
   mininet> h1 ip addr flush dev h1-eth0
   mininet> h1 ip addr add 10.0.0.1/24 dev h1-eth1

4. Re-ping h3 -- should still succeed, now routed entirely through s2:
   mininet> h1 ping -c 3 h3

5. Watch the CONTROLLER terminal while step 4 runs. You should see:
   [MOBILITY] host=00:00:00:00:00:01 moved from dpid=1 port=1 to dpid=2 port=4
   [VLAN-ASSIGN] host=00:00:00:00:00:01 role=staff -> VLAN=10 (dpid=2 port=4) <-- re-learned (mobility)
   That log line, live, is the proof: same policy file, same VLAN, zero
   reconfiguration -- just a different physical attachment point.

To reset back to the original wiring before re-running the whole demo:
   mininet> py net.configLinkStatus('h1', 's2', 'down')
   mininet> py net.configLinkStatus('h1', 's1', 'up')
   mininet> h1 ip addr flush dev h1-eth1
   mininet> h1 ip addr add 10.0.0.1/24 dev h1-eth0
